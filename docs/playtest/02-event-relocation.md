# 把事件搬到起點旁邊：走不到的畫面怎麼驗

有些原版行為只在遊戲最後才看得到 —— 結局控制室要通關才進得去，而自動化
流程沒辦法從頭玩到那裡，手上也沒有走得到那裡的存檔。

不必放棄驗證：**事件的觸發地點寫在資料裡，不在程式裡**。把那一格的事件
搬到起點旁邊，跑的仍然是原版自己的程式碼，只有「站在哪裡才觸發」被改了。

工具是 [`cmd/mm2patchevent`](../../cmd/mm2patchevent)。

## 怎麼用

```bash
# 先看這一段現在有哪些事件與腳本
go run ./cmd/mm2patchevent -list

# 把 `0e fd`（結局控制室）接成新腳本，並把起點北邊那一格改指到它
go run ./cmd/mm2patchevent \
    -out workplace/dosbox/game/EVENTSI.DAT \
    -segment 0 -cells 39,54,56 -retarget 71 -script 0efd

# 走一步就會觸發
tools/dosbox_run.sh ega "wait:4;key:Return;wait:2;key:s;wait:4;key:g;\
wait:5;key:z;wait:4;key:Up;wait:8;shot:control"
```

**輸出一定要寫到 `workplace/dosbox/game/`**（DOSBox 的可寫副本）。
`workplace/orig/` 是唯讀參考，驗完把那個檔案還原回去。

## 三件驗證之前不知道、會讓人白跑一輪的事

**格號是 `Y × 16 + X`，而北是 Y 增加。** 隊伍從 Middlegate 的 (7, 3) 面北開始，
按一次 `Up` 之後在 **(7, 4)**，也就是格 71。先前按「北是 Y 減少」猜，
事件加在格 39 上，走一步當然什麼都不會發生 —— 而**什麼都不會發生與
「機制沒接上」長得一模一樣**，很容易往錯的方向查。

**起點附近的格子大多已經有事件了。** 原版取事件表裡第一筆相符的，所以在
已經有事件的格子上再加一筆，新的那筆永遠不會被取到。要改那些格子得用
`-retarget`（改既有那筆的腳本編號），不是 `-cells`。

**這件事要用記憶體傾印確認，不要用畫面猜。** `tools/dosbox_run.sh` 的
timeline 有 `dump:NAME`，把 DOSBox 行程的匿名記憶體整個倒出來。
DGROUP 的基底可以直接找出來：`ds:0000` 起那 48 個位元組在 `MM2.EXE` 的
`0x8630` 起（`EXE 檔內偏移 = DGROUP 偏移 + 0x8630`），拿去搜傾印檔
**只會命中一處**。命中之後用三個會變的值交叉檢查基底對不對：
`ds:0426` 是隊伍人數（6）、`ds:0392` 是城號（Middlegate 是 0）、
`ds:0393`／`ds:0394` 是 X／Y。

```python
exe = open('workplace/orig/MM2/MM2.EXE', 'rb').read()
mem = open('workplace/dosbox/shots/<dump>.bin', 'rb').read()
base = mem.find(exe[0x8630:0x8630 + 48])       # 只會有一個
print(mem[base + 0x0426], mem[base + 0x0393], mem[base + 0x0394])
```

**傾印檔用完就刪，不要留著。** 一次 `dump:` 是 112 MB，十九份就 2.1 GB，
而它們**再跑一次就有**（同一條 timeline 是決定性的）。留下來的只有結論與
上面那段重算基底的程式碼。同一個目錄裡的 `.png` 佔的是幾 MB，那些要留。

事件表的執行時副本在 `ds:6052`（`SS == DS`，小模式），一筆 3 bytes ——
改完的表在不在記憶體裡，看那裡就知道，不必從畫面反推。

## 驗到的事：守門的旁白印在載入之前

`_2smith_e01` 在第 19–22 列印 `ds:58B8` 那四格指標指到的字串，而填這四格的
`sub_1D2A4` 要到同一支函式的**結尾**才被呼叫。靜態面四項證據都指向
「第一次進控制室時印的是 `ds:0000`」，但**指標間接寫入不會留下 `58B8h`
這個字面值**，靜態掃描排除不了那條路。

兩個獨立的實機觀測把它定案：

1. **記憶體傾印**：進到第一人稱視角、走一步之後各傾印一次，
   `ds:58B8`–`ds:58BF` **八個位元組全是 0**。這一步關掉的正是靜態掃描
   關不掉的那個洞 —— 沒有任何間接寫入碰過它。
2. **畫面**：把 `0e fd` 搬到起點旁邊觸發，第 19–22 列印出來的是

   ```
   = Version 1.01
     Version 1.01
     Version 1.01
     Version 1.01
   ```

   `ds:0000` 的內容正是 `F9 C3 "Version 1.01"` —— 四個空指標各印一次，
   行首那個符號就是 `F9 C3` 兩個位元組被當成字元畫出來的樣子。

所以那一段旁白**在原版第一次進控制室時是壞的**，要到第二次進來才正確。
等級由**強推論**升為**已證實**。remake 照正確版本印 —— 這是刻意的差異，
不照抄一個玩家看得出來是壞掉的畫面。

重跑指令（`-retarget 71` 那一行）與上面相同。驗完記得把
`workplace/dosbox/game/EVENTSI.DAT` 還原成原版那一份。
