# 交易、使用、裝備、卸下、丟棄：`2CMDS`

輸入檔：`MM2.EXE` ＋ `2CMDS.OVL` ＋ `ITEMS.DAT`（SHA-256 見
[`inventory.md`](../inventory.md)）。IDA 位址取自
`workplace/ida/out/2CMDS.asm`，函式邊界由 `tools/ida_funclist.py` 取得。

五個進入點對應探索畫面的五個指令：

| 進入點 | 位址 | 大小 | 指令 |
|---|---|---|---|
| `_2cmds_e00` | `0x1C48E` | 426 | **交易**（金錢／寶石／食物／物品）|
| `_2cmds_e01` | `0x1C6F2` | 245 | **使用**（裝備 `1`–`6`、背包 `A`–`F`）|
| `_2cmds_e02` | `0x1C7E8` | 194 | **卸下**（`1`–`6`）|
| `_2cmds_e03` | `0x1C9E6` | 419 | **裝備**（`A`–`F`）|
| `_2cmds_e04` | `0x1CB8A` | 138 | **丟棄** |

---

## 1. 角色記錄的六排

`2CMDS` 的算式一路用 `0x82`（130）當 stride、`ds:7E20` 當名冊基底，
再加常數偏移。還原之後是六排各六個位元組：

| 偏移 | 內容 |
|---|---|
| `+40`（`+0x28`）| 裝備的物品編號 |
| `+46`（`+0x2E`）| 裝備的充能 |
| `+52`（`+0x34`）| 裝備的屬性 |
| `+58`（`+0x3A`）| 背包的物品編號 |
| `+64`（`+0x40`）| 背包的充能 |
| `+70`（`+0x46`）| 背包的屬性 |

**兩組六格**，裝備在前、背包在後 —— 與 `2SMITH` 的商店工作區同一套
（[`07`](07-2smith-shop.md) §1）。

`sub_1C130(角色, 起始槽)` 是**裝備排的往前壓縮**：從指定槽起把後面
每一格的三個欄位往前搬，最後一格（`+45`／`+51`／`+57`）清 0。
卸下時用它，所以裝備排不會留洞。

## 2. 訊息表 `ds:3378`

`sub_1C180(n)` 置中印 `ds:3378[n]` 一行，停 50。**`n ≥ 0x13` 時前後
各加一個裝飾字串**（`ds:3378[0]` ＝ `* `、`[1]` ＝ ` *`）。

| n | 內容 | n | 內容 |
|---|---|---|---|
| 02 | `Full` | 0B | `Already have one` |
| 03 | `CURSED` | 0C | `Not with shield` |
| 04 | `Wrong class` | 0D | `Not with 2 handed weapon` |
| 05 | `Wrong alignment` | 0E | `Not equippable` |
| 06 | `Already have weapon` | 0F | `No special power` |
| 07 | `Already have missile weapon` | 10 | `No charges` |
| 08 | `Already have shield` | 11 | ` Done ` |
| 09 | `Already wearing armor` | 12 | `Spell Failed` |
| 0A | `Already wearing helm` | 13 | `Hireling is happier!` |
| | | 14 | `Too much!` |

`0x13` 與 `0x14` 就是那兩個帶星號的 —— 交易失敗與給雇傭兵東西時用。

## 3. 物品的六個類別（編號區間）

六支各 24 bytes 的判定函式，內容只有一個區間比較：

| 函式 | 編號區間 | 類別 |
|---|---|---|
| `sub_1CFDE` | 1–65（`0x01`–`0x41`）| 單手武器 |
| `sub_1CFF6` | 66–91（`0x42`–`0x5B`）| 雙手武器 |
| `sub_1D00E` | 92–114（`0x5C`–`0x72`）| 遠程武器 |
| `sub_1D026` | 115–126（`0x73`–`0x7E`）| 盾 |
| `sub_1D03E` | 127–154（`0x7F`–`0x9A`）| 護甲 |
| `sub_1D056` | 155–159（`0x9B`–`0x9F`）| 頭盔 |

`sub_1D06E(編號)` ＝ 單手 ＋ 雙手，也就是「這是不是近戰武器」。

六個區間**首尾相接、不重疊**，160 以上不屬於任何一類（也就裝備不了，
訊息 `Not equippable`）。這與 `2SMITH` 鑑定畫面的兩段判斷
（`< 0x6F` 印傷害、`0x73`–`0x9F` 印防護）是獨立的第二套邊界，
兩者在護甲那一段吻合、在武器那一段不同 —— **原版有兩套不同的界線，
不是同一張表**。

## 4. 已經裝了什麼（六支 70 bytes 的掃描器）

形狀都一樣：掃裝備排 `+40` 的六格，任一格屬於指定類別就回 1。

| 函式 | 掃哪一類 |
|---|---|
| `sub_1D0D6` | 雙手武器（`sub_1CFF6`）|
| `sub_1D11C` | 盾（`sub_1D026`）|
| `sub_1D162` | 遠程武器（`sub_1D00E`）|
| `sub_1D1A8` | 護甲（`sub_1D03E`）|
| `sub_1D1EE` | 頭盔（`sub_1D056`）|
| `sub_1D234` | 近戰武器（`sub_1D06E`，單手或雙手）|

## 5. 裝備的衝突規則（`sub_1C8AA`）

`sub_1C8AA(角色, 背包槽)` 依背包那一格的編號決定要檢查什麼，回訊息號：

| 要裝的是 | 檢查 | 擋下時的訊息 |
|---|---|---|
| 單手武器 | 已有近戰武器（`1D234`）| 06 `Already have weapon` |
| 雙手武器 | 已有近戰武器（`1D234`）| 06 |
| 雙手武器 | 已有盾（`1D11C`）| 0C `Not with shield` |
| 遠程武器 | 已有遠程（`1D162`）| 07 `Already have missile weapon` |
| 盾 | 已有雙手武器（`1D0D6`）| 0D `Not with 2 handed weapon` |
| 護甲 | 已穿護甲（`1D1A8`）| 09 `Already wearing armor` |
| 頭盔 | 已戴頭盔（`1D1EE`）| 0A `Already wearing helm` |

**雙手武器與盾互斥，而且兩個方向各有自己的訊息** —— 先裝盾再拿雙手武器
說 `Not with shield`，反過來說 `Not with 2 handed weapon`。

## 6. 交易（`_2cmds_e00`）

標題 `ds:33AF` ＝ ` Trade:  `，四個選項是四個指標變數：
`1) Gold`／`2) Gems`／`  3) Food`／`  4) Item`。
選完問 `With (1-N)?`（`ds:33B9` ＋ 人數 ＋ `ds:33C2`），
對象編號經 `ds:03B4` 轉成隊伍索引。

**選項 1（金錢）對雇傭兵不開放**：`ds:0416[來源] >= 0x18` 時那個鍵直接無效。

| 函式 | 給什麼 | 欄位 | 上限 |
|---|---|---|---|
| `sub_1C212` | 金錢 | `+102`，32 位元 | 讀四位數（`loc_170DE(4)`）|
| `sub_1C2A4` | 寶石 | `+92`，16 位元 | 同上 |
| `sub_1C304` | 食物 | `+37`，8 位元 | **40**（`0x28`），超過就 `Too much!` |
| `sub_1C3A6` | 物品 | 背包三排 | 對方背包滿 → `Full` |

三支數值型的形狀相同：印 `How Much? ` → 讀數 → 來源不夠就訊息 `0x14`
→ 扣來源 → **對象編號 > 0x17（雇傭兵）時不加給對方，改印
`Hireling is happier!`（訊息 `0x13`）**。錢真的從來源身上消失，只是沒人收到。

## 7. 使用（`_2cmds_e01`）

問 `Use Which (A-F)/(1-6)?`：`1`–`6` 是裝備排、`A`–`F` 是背包排。
選中之後查物品記錄（`20 × 編號 + 0x6960`）的 `+0x0F`：

	+0x0F == 0        → 訊息 0x0F `No special power`
	充能（該排 +46／+64）== 0 → 訊息 0x10 `No charges`
	+0x0F >= 0x80     → sub_1CED8：施法（法術編號 = +0x0F）
	否則              → sub_1CF34：非魔法效果，訊息 0x11 ` Done `

背包那一支（`sub_1C638`）用完充能會把編號設成 **`0xFF`** 而不是 0，
屬性清 0；裝備那一支（`sub_1C6A0`）不做這件事。

## 8. 卸下（`_2cmds_e02`）與裝備（`_2cmds_e03`）

卸下：問 `Remove Which (1-6)?` → 背包滿就 `Full` → `sub_1CD54`
把那件的加成從角色身上扣掉 → 三個欄位搬到背包第一個空格 →
`sub_1C130` 把裝備排往前壓縮。

裝備：問 `Which (A-F)?` → `sub_1C8AA` 過關 → **先把背包那一格的三個欄位
（`+58`／`+64`／`+70`）抄進裝備那一格（`+40`／`+46`／`+52`）** →
`sub_1CE12` 把加成加上去 → `loc_171B6` 從背包移除。
順序這樣排是必要的：加成是從**裝備槽**讀出來算的。

### 加成怎麼算（`sub_1CC14`／`sub_1CC54`／`sub_1CCD4`）

`sub_1CC14(記錄, n, &當前欄位指標)` 回傳兩個位址：

	回傳值   = 記錄 + 0x10 + n          ; 基礎那一份，一定有
	出參     = 記錄 + 0x6B + n，n > 5 時是 0   ; 當前值那一份，只有六個屬性有

`sub_1CCD4`（裝上）與 `sub_1CC54`（卸下）形狀相同：

	物品 = 20 × 記錄[+40+槽] + 0x6960
	n    = 物品[+0x0E] >> 4             ; 加哪一格
	量   = 物品[+0x0E] & 0x0F           ; 加多少
	量 == 0 → 什麼都不做
	量 += 記錄[+52+槽] & 0x3F           ; 再加上這一槽的附魔等級
	兩個欄位各做一次：裝上走 root 0x13608（飽和加，上限 255）
	                  卸下走 root 0x135F0（飽和減，下限 0）
	最後 loc_1768A 重算防護等級

`n` 的值域 0–15，對到記錄 `+16`–`+31`：六個屬性、八種抗性、盜行、
裝備防護值。逐件與物品名字對得上，見
[`02-data-files.md`](../formats/02-data-files.md)「`+0x0E`：裝備加成」。

`sub_1CE12`／`sub_1CD54` 除了呼叫上面那一對，還處理武器欄：
讀物品 `+0x10`，`sub_1D06E` 認得的（武器類）就把 `+76`（骰面）與
`+77`（加成）寫上或清掉。

## 9. 用到的 thunk

| thunk | 目標 | 用在哪 |
|---|---|---|
| `sub_16EC2` | root `0x13268` | 讀一個落在指定範圍的鍵 |
| `loc_170DE` | root `0x12F1A` | 讀一個 N 位數 |
| `sub_171CE` | root `0x13608` | 套用物品效果（裝上與 `sub_1CF34` 共用）|
| `sub_1770E` | root `0x128B6` | `_2cmds_e03` 裝備前的前置檢查 |
| `loc_171B6` | root `0x13766` | 從背包移除一格 |
| `loc_1768A` | root `0x14F3A` | 重算防護等級 |
| `loc_171DA`／`loc_171C2` | root `0x1545A`／`0x154AE` | 用物品施法的前後處理 |
| `loc_170C6` | 2CAST1 `+D0C2` | 真正的施法入口 |

## 10. 未解

  前兩格與其餘的量級差很多，當成「隊伍索引轉換表」是依呼叫端推的，
  語意未證實。
- 訊息 03 `CURSED`、04 `Wrong class`、05 `Wrong alignment`、
  0B `Already have one` 的觸發點不在這個 overlay 裡。
