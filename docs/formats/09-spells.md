# 法術系統

## 1. 一套編號貫穿三處

`SPELLS.DAT`、`2CAST1.OVL` 與 `2CAST2.OVL` 的跳表，用的是同一套 **0–95**
的法術編號：

```
0–47   巫師系（職業 2 弓箭手、職業 4 巫師）
48–95  牧師系（其餘職業）
```

分派寫在 root 的 `sub_15644`：

```asm
cmp  byte [bx+0Fh], 2      ; 弓箭手
je   不加
cmp  byte [bx+0Fh], 4      ; 巫師
je   不加
add  [bp-4], 30h           ; 其餘職業 +48
不加:
ax = [bp-4] * 2 + 7D60h    ; SPELLS.DAT 載入位置
```

**旁證**：`2CAST1` 的跳表第 0 項與第 49 項指向同一支 handler
（`sub_1CBEC`）。第 0 項是巫師系第 1 條、第 49 項是牧師系第 2 條 ——
兩者在手冊裡都是「喚醒術」。

`data/spells.json`（抄自手冊）的順序相反，所以 `cmd/mm2data` 產生
`spellcosts.json` 時就把兩半對調成手冊的順序。

## 2. 施法代價

見 [`02-data-files.md`](02-data-files.md) §9。摘要：

```
A 位元 0–5    寶石消耗（超過 50 的一律當成 100）
B 位元 0–3    固定法力消耗
B 位元 4–6    每施法者等級的法力消耗
```

法力 = `固定 + 每等級 × 施法者等級`。

**算出來的代價不等於扣掉的代價。** 兩份值分別放在 `ds:9E0C`（法力）與
`ds:9E46`（寶石），扣費（root `sub_15D1A`）排在效果之後，中間處理常式
可以覆寫 —— 取消選物品會把兩個歸零，加強法力會把法力那一份換掉。

## 3. 會不會：角色記錄 +81

六個位元組 48 個位元，一位一條，低位在前。`Character.Knows(n)` 與
`Learn(n)` 走這個遮罩。

## 4. 效果：兩張跳表把 96 條不重不漏地分完

| 表 | 映像偏移 | 筆數 | 預設出口 | 索引 | 實作 |
|---|---|---|---|---|---|
| `2CAST1.OVL` | `0xD1CE` | 96 | `0xD28E` | 法術編號 | 43 |
| `2CAST2.OVL` | `0xD084` | 92 | `0xD13C` | **法術編號 − 2** | 53 |

每一筆不是預設出口，就是指向一個六位元組的 trampoline
（`E8 rel16` 呼叫 handler ＋ `E9 rel16` 跳共同出口）；trampoline 連續排列，
`2CAST1` 從 `0xD0D8` 起、`2CAST2` 從 `0xCF46` 起，步長都是 6。

**43 + 53 = 96，重疊 0，沒有實作的也是 0。** 兩張表把全部法術剛好分完，
一條不重複一條不漏 —— 這是表的幾何解對了的判準，而且它比結構條件更強：
`2CAST2` 的表**以「法術編號 − 2」索引**這件事，光看結構看不出來，
是分割條件逼出來的。

geometry 由三個條件夾定：

1. 每一筆是預設出口或落在 trampoline 區、且 6 對齊。
2. 表尾正好接上預設出口的位址（`0xD084 + 92×2 = 0xD13C`）。
3. 兩張表的實作集合不重不漏地蓋滿 96 條。

只用前兩條會得到「`2CAST2` 是 92 筆、索引就是法術編號」，
於是重疊 22、22 條沒人實作 —— 第三條才把那兩筆錯位抓出來。

兩張表都用 **`SPELLS.DAT` 的順序**索引：`0–47` 巫師、`48–95` 牧師
（引擎內部的 `data/spells.json` 是反過來的，換算在 `cmd/mm2data`）。

| 引擎編號 | 法術 | handler | 效果 |
|---|---|---|---|
| 3 | 急救術 | `sub_1CC5C` → `sub_1CE46(8)` | 狀況 `&= 2Fh`，生命 +8 |
| 7 | 治傷術 | `sub_1CCA8` → `sub_1CE46(0Fh)` | 狀況 `&= 2Fh`，生命 +15 |
| 16 | 解毒術 | `sub_1CCD6` | 狀況 `&= 77h` |
| 22 | 治病術 | `sub_1CD16` | 狀況 `&= 7Bh` |
| 30 | 恢復術 | `sub_1CD56` | 狀況 `= 0` |
| 33 | 解除石化 | `sub_1CD96` | 狀況**整個等於** `82h` 才作用，清成 0 |

前五條都先檢查 `狀況 >= 80h`，是的話沒有效果。

**這七條反過來把狀況位元組（記錄 `+38`）的語意定出來**：每一支清掉哪幾位，
那幾位就是它治的東西。

| 位元 | 語意 | 誰清掉 |
|---|---|---|
| 2 | 疾病 | 治病術 |
| 3 | 中毒 | 解毒術 |
| 4 | 急救術治的那一項 | 急救術、治傷術 |
| 6 | 無意識 | 急救術、治傷術（`sub_1AFBC` 在生命歸零時設）|
| 7 | 嚴重（死亡／石化的高位）| — |

而 `82h` = 石化、`81h` = 死亡 —— 那兩條用 `cmp` 比整個位元組，不是測位元。

**代價的交叉驗證**：這七條的 `SPELLS.DAT` 值與手冊逐條相符 ——
1 SP、2 SP、3 SP、4 SP、5 SP+5 寶石、6 SP+6 寶石、7 SP+7 寶石。
七條全中，等於把上一節的欄位切法又驗了一次。

### 兩條要玩家輸入數字的傳送

原版用 `sub_16EC2(下限, 上限)` 讀一個按鍵，`0x1B` 表示取消。

**傳送術**（`sub_1C590`）讀 `1`–`9`，往面向的方向走那麼多格。
**每一步各自 `and 0Fh`**，不是一次加完再遮罩 —— 走九格會真的
繞一圈，落點與「加九再取模」不同。同樣不查牆。

**城市傳送術**（`sub_1CA20`）讀 `1`–`5`，`ds:0392 = 鍵 - 31h`
（地圖 0–4 是五座城），然後把 X 與 Y **都設成 `0FFh`**。
root 在 `ds:0393 == 0FFh` 時改用 `ATTRIB` `+14` 的預設進入座標 ——
**落點是資料決定的，法術本身沒有座標表**。

### 狂暴術

`sub_1CC64` 的順序有個小瑕疵，引擎照抄：

	一場戰鬥只能一次（ds:9FC1）
	目標狀況必須是正常（+38 == 0）
	+38 = 40h（昏迷）        ← 先設
	+115（耐力）為 0 就到此為止   ← 後檢查
	+115 減一
	+94（目前生命）= 0
	傷害 = (+76 武器骰 + +77 命中加值 + 10) × 2，打 10 隻

**耐力為 0 的人會白白昏過去** —— 狀況在檢查之前就寫下去了。

手冊說這條「失去 1 點之耐力」，程式碼減的是 `+115`，兩者一致：
記錄的屬性區六格是力量／智慧／人格／速度／準確度／運氣，
耐力不在區塊裡，它在 `+39`（基礎）與 `+115`（當前）。

### 自然之門

`sub_1C7DA` 是唯一落點隨遊戲內日期變動的法術。

	前提：ds:03CA == 9（**現代**，見下），且這張圖沒禁傳送
	day = ds:03B4（word）
	索引 = 12（預設）
	若 day 是**單數**：從 ds:30E0 的十三個門檻裡找第一個大於 day 的，
	                   那一格的索引就是答案
	若 day >= 150：索引 = 11，且 **ds:03CA 改成 8**
	地圖 = ds:30FA[索引]
	座標 = ds:3108[索引]（低 nibble X、高 nibble Y）

門檻表：`20 40 60 80 93 94 100 120 130 140 150 181 255`
地圖表：`11 14 33 9 37 8 37 6 14 39 8 11 11 0`

**偶數日一律用預設的 12**，所以門只有單數日才會換位置 ——
手冊的「隨時間（日／年）而改變」講的是這個。

**`ds:03CA` 是世紀槽號，不是任務階段。** 日期與年份各是十格的表，
`ds:03CA` 選其中一格（[`11-time-and-light.md`](11-time-and-light.md)）；
9 是現代，時光機（`2CAVES` 的 `_2caves_e08`，玩家按 `5`–`8`）把它改成 5–8，
事件腳本的 `0x22` 也拿它做世紀範圍檢查（[`07-event-script.md`](07-event-script.md)）。

所以這條法術**只有在現代開得了門**，而 `day >= 150` 那一步把 `ds:03CA`
改成 8 —— 那不是「把法術鎖起來」，是**把隊伍送進另一個世紀**（副作用才是
之後開不了門，因為前提要 9）。回得來的路是休息：`2MISC` 的 `sub_1CD8A`
在 `ds:03CA != 9` 時擲 `rand(1,60)`，小於 10 就把它設回 9 並以
`X = Y = 0xFF` 重新進圖（＝該圖的預設入口）。**六分之一，所以平均六次**
—— 與《軟體世界》攻略說的「一直用 Rest，大約七八次就能睡回現代」對得上。

	E 33 35 37 40

二十個值全是野外地圖編號。落點與城市傳送術一樣把 X／Y 設成 `0FFh`，
交給 `ATTRIB` `+14`。

### 魯易浮標

`sub_1C340` 讀 `1`–`2`：`1` 把現在的位置記進 `ds:03E8`（地圖）與
`ds:03E9`（`(Y << 4) + X`），`2` 讀回來。座標打包方式與 `ATTRIB`
`+14` 相同。

`ds:03E8`／`ds:03E9` 落在隊伍全域那一段（`ds:03D5` 起的那批計數器
旁邊），所以它跟著存檔走。

### 穿透術

`sub_1C722` 往面向的方向走一格，**完全不查牆** —— 這是全遊戲唯一
一條略過牆判定的移動。

	ds:0393 = (ds:0393 + dx) and 0Fh      ; X
	ds:0394 = (ds:0394 + dy) and 0Fh      ; Y
	ds:0395 = 1                            ; 要求重畫
	ds:039B = 0                            ; **不觸發落點那一格的事件**

**兩個軸各自遮罩**，不是把 `Y*16+X` 當成一個線性索引去減一。差別只在
邊角：從 (0,0) 往西只有 X 繞回去，落在 **(15,0)**；線性索引的模型會落在
(15,15)。社群站上寫的是後者，與這段碼對不上（見
[`docs/research/07`](../research/07-blurglecruncheon.md)）。

`ds:039B` 是「剛剛移動過」的旗標：一般移動之後設 1，root `0x15CF4` 讀它 ——
`ds:039B != 0` 且腳下那一格的屬性層有事件位元（`ds:59C8 >= 0x80`）才設
`ds:042E = 1`。穿透術把它清成 0，所以**穿牆落地不會踩到落點的事件**。
這是靜態就讀得出來的，不必進遊戲試。

### 跳躍術

`sub_1C23E` 只在室內有效（`cmp ds:039D, 1 / je 失敗`，而它接下來查的
是室內那套牆位元組 `ds:59D6`／`ds:59C6`）。兩道牆各查一次：
目前格朝面向那面，以及中間格朝同一面。兩道都通得過才落在第二格：

	ds:0393 = (中間格 X + dx) and 0Fh
	ds:0394 = (中間格 Y + dy) and 0Fh

中間格本身也是 `and 0Fh` 算出來的，所以跳躍會跟著繞回對邊 ——
與一般移動同一套。

### 復活與年齡

`sub_13B68(記錄, n)` 是共用的加齡程序：`+33` 加 n，**上限 200**。

復活（`sub_1CAA4`）只對 `+38 >= 80h`（石化與死亡那一類）有效，
代價分三筆：

	sub_13B68(施法者, 1)      ; 施法者老一歲
	sub_13B68(目標, 5)        ; 目標老五歲
	+39 為 0 → 失敗
	+39 減一，同時寫進 +115   ; 幸運的兩份一起改
	+38 = 0                   ; 狀況清成正常

**幸運歸零就再也救不回來** —— 那是復活次數的上限。
`+39` 與 `+115` 一起寫這件事也確認了兩者是同一個值的兩份。

回春術（`sub_1C994`）也走加齡程序，但方向由擲骰決定：

	年數 = rand(1, 10)        ; 先擲年數
	擲值 = rand(1, 100)       ; 再擲成敗
	擲值 < 50 且年齡 >= 18 → 年齡減年數
	否則                    → 年齡加年數（走 sub_13B68）

**兩次擲骰一定都會發生**，成敗只決定年數的正負號。未滿 18 歲
一律變老 —— 那道年齡下限擋的是「一直回春回到出生」。

「選一名隊員」那批法術在原版走 `sub_1CF8C` 選單（回傳 `0x1B`
表示取消）。引擎用 `Session.Target` 代替，負值表示施法者自己。

### 兩條動到背包物品的

兩條都用**施法者自己**的背包（`ds:5DD6`），不是選隊員；
選物品走 `sub_1CB48`（回傳 `0x1B` 表示取消）。

**能量補充術**（`sub_1C648`）：`+64 + 槽位`（充能）加 `rand(1,6)`。
欄位本來就是 0 的直接失敗 —— 「這件東西沒有充能」與「充能用完」
共用同一個 0，所以用完就補不回來。

**加強法力**（`sub_1C774`）：`+70 + 槽位`（屬性）的低六位加一，
高兩位原樣保留。

**代價是 `50 × 施法前的低六位`，而且它是這一輪真正扣的那一筆** ——
這支常式把 `ds:9E0C` 整個覆寫掉（`mov al, 32h; mul var_2; mov ds:9E0C, ax`），
法術表算出來的值就此作廢，而扣費排在它之後。兩個後果：

- **等級 0 的物品升第一級不用錢**（50 × 0 = 0）。
- 之後每升一級多 50 點，**越高越貴**。

自己那道檢查比的是記錄 `+88`，而那時候還沒扣費，所以看的是施法前的法力。
低六位到 `0x3F` 時仍然會再加一，進位撞進 bit 6 —— 引擎照抄，不修。
社群把這條列為 Bug 4，見 [`docs/research/07`](../research/07-blurglecruncheon.md)。

**複製術**（`sub_1C68C`）：把選中的那件抄到第一個空槽，
三個平行陣列（`+58` 編號、`+64` 充能、`+70` 屬性）一起抄。
**編號 `0xD0` 以上抄不了** —— 那道門檻擋掉的是任務物品那一段。

**去咒術**（`sub_1CB10`）：只在 `+64 + 槽位` 等於 `0xFF` 時動手，
把它改成 1。所以**充能欄的 `0xFF` 就是「被詛咒」的標記** ——
那一欄同時是充能次數與詛咒旗標，`0xFF` 是保留值。

這也解釋了能量補充術為什麼不能對 0 動手：`0` 是「沒有充能」、
`0xFF` 是「被詛咒」，中間才是真的次數。

### 兩條動到角色記錄的

**喚醒術**（`sub_1CBEC`，兩系都有）整隊掃過去，狀況位元組低於 `0x80`
的做 `and [記錄+38], 6Fh`。`0x6F` 清掉 `0x80` 與 `0x10`，而
`0x80` 那一路根本進不來 —— 所以它只清 `0x10`。一條叫「喚醒」的
法術唯一做的事就是清這個位元，**`0x10` 是沈睡**。

**回復陣營**（`sub_1C8F0`）把 `+13` 抄到 `+106`。所以
**`+13` 是原始陣營、`+106` 是目前陣營** —— `+106` 原本夾在金錢
（`+102`–`+105`）與屬性當前值（`+107`）之間，是個沒認出來的空格。

### 2CAST1 只管非戰鬥法術

把 43 支 handler 對回法術名之後看得很清楚：`2CAST1` 收的全是
「非戰鬥用」與「任何時刻」那兩類，**攻擊法術一條都不在裡面**。
戰鬥法術整批在 `2CAST2`。

### 狀態類：`ds:9FC2` 的九個代碼

代碼減一之後同時索引兩張表：位元遮罩表 `ds:1022`
（`02 04 08 10 20 40 80 00`）與名稱表 `ds:0FEA`。位元 OR 進
`ds:9F86[槽位]` —— 那是怪物的狀態位元組。代碼 8、9 不設位元，
直接走死亡處理（`sub_18AF4`）。

| 1 | `0x02` | silenced | 沈默 |
| 2 | `0x04` | weakened | 衰弱 |
| 3 | `0x08` | frightened | 驚嚇 |
| 4 | `0x10` | slept | 沈睡 |
| 5 | `0x20` | held | 定身 |
| 6 | `0x40` | mindless | 心智渙散 |
| 7 | `0x80` | encased | 封困 |
| 8 | — | killed | 死亡 |
| 9 | — | disintegrated | 粉碎 |

**`0x18582` 一次 `test 0xB0`** —— 沈睡、定身、封困三個位元擋住行動，
其餘四個不擋。另外幾處各自單獨測：`0x1863A` 測沈默（不能施法）、
`0x18447` 測衰弱、`0x183F1` 測驚嚇、`0x184A1` 測心智渙散、

### 抗性：三層

`sub_1714A` 的開頭把目標數夾在場上怪物數（`ds:0508`）之內，然後：

1. **抗魔法**：`ds:9E31` 非 0 時擲 `rand(施法者等級, 90)`，
   抗性大於擲值就擋下整個法術。
2. **屬性抗性**：前一層沒擋下且屬性不為 0 時查 `sub_18674(屬性 - 1)`
   —— 讀 `ds:9E36[屬性-1]`，**非 0 就完全免疫**，沒有機率可言。
3. **減半層**：擲 `rand(1, 191)`，不超過 `ds:9680[目標]` 時 ——
   傷害類**減半**（`shr ds:9FC6, 1`）、狀態類代碼小於 9 的**完全擋下**，
   代碼 9（粉碎術）改判 50 點傷害（`ds:9FC6 = 0x32`、`ds:9FC3 = 0`）。

   `ds:9680` 是場上每個位置的**怪物編號**（`sub_13B80` 拿它當
   `MONSTERS.DAT` 的索引去解記錄，`0x18228` 的佈場程序寫入）。
   怪物表照難度排序，所以編號本身就是強度 —— 這一層等於
   「越後面的怪越常吃到減半」，編號 191 以上必定減半。

最後若傷害是 0 也視為無效。

`ds:9E31` 來自怪物記錄 `+17` 的高 3 位元查 `ds:4DC0`：

	[0, 10, 20, 35, 50, 75, 90, 100]

解包在 `2COMBAT.img` 的 `0x13E1E`，同一個位元組拆成五份：
bit 3–4 進 `ds:9E30`、bit 5–7 **`& 7`** 之後查表，bit 0/1/2 則是
屬性抗性的其中三格（見下）。擲值上限是 90，所以理論上抗性 100
必定擋下 —— 但**256 隻怪物的索引只用到 0–6，第八格沒人用到**
（分佈 `{0:140, 1:4, 2:13, 3:44, 4:25, 5:18, 6:12}`）。

### 屬性抗性的七個旗標

`ds:9E36`–`9E3C` 七個位元組，索引 = 屬性參數減一。原版把它們從
怪物記錄的三個位元組的高位拆出來（`2COMBAT.img` `0x13D7A`–`0x13E19`）：

| 屬性 | 位址 | 來源 | 有旗標的隻數 |
|---|---|---|---|
| 1 火 | `ds:9E36` | `b23` bit 6 | 105 |
| 2 電 | `ds:9E37` | `b23` bit 7 | 68 |
| 3 冷 | `ds:9E38` | `b22` bit 6 | 170 |
| 4 酸 | `ds:9E39` | `b22` bit 7 | 100 |
| 5 睡 | `ds:9E3A` | `b17` bit 1 | 61 |
| 6 法術狀態 | `ds:9E3B` | `b17` bit 0 | 61 |
| 7 未定 | `ds:9E3C` | `b17` bit 2 | 54 |

`b22`、`b23` 的低五位是 AC 與傷害骰面數，高兩位一直是空的 ——
抗性旗標就塞在那裡。名字帶 `Fire` 的四隻全部有火旗標、零例外，
`Frost Dragon` 有冷旗標。

三層抗性與狀態的施加都已實作。**各狀態的持續時間與解除條件**
還沒解（在 `2COMBAT` 裡，`0x195BA` 把整個位元組清 0 是其中一處）。

手冊寫的傷害範圍是骰子式的（`2—8`＝2d4、`10—100`＝10d10……），
**上界與程式碼逐條相符，下界只有月光術對得上**。程式碼是裁決者，
表列的是程式碼的值；手冊那一欄的差距記在
`CONTEXT.md` §5。目標數目前取自手冊，等級是**強推論**。

### 隊伍增益與戰鬥旗標

`sub_1D13E` 與 `sub_1D170` 只是印字串（`ds:31CA`／`ds:31D3`）再暫停，
不是效果 —— 效果就在 handler 自己那三、四行。兩種形狀：

**全域計數器**（`cmp ds:XXXX, 0FFh / jae 跳過 / inc ds:XXXX`），
與 `2CAST1` 那十二條同一個形狀：

| 引擎編號 | 名稱 | 計數器 |
|---|---|---|
| 2 | 祝福術 | `ds:03E3` |
| 64 | 隱身術 | `ds:03E4` |

### `ds:59A0`：禁止哪些法術

`ds:59A0` 是 **`ATTRIB` 記錄的 `+26`**，隨地圖一起載進來 ——
在十四個 overlay 裡只有讀、沒有寫，連 root 也沒有寫入指令。
認出來的線索是 `ds:5994`：root 在 `ds:0393 == 0FFh` 時拿它當預設
進入座標拆 nibble，那正是 `+14`，於是記錄基底 `ds:5986` 也就定了。
被測到的五個位元各自對到具體法術：

| 位元 | 擋住的法術 | 測試處 |
|---|---|---|
| `0x01` | 陷敵術 | `2CAST2` `0x1C69C` |
| `0x08` | 時間扭曲 | `2CAST2` `0x1C594` |
| `0x10` | 傳送術 | `2CAST1` `0x1C5A6` |
| `0x20` | 穿透術 | `2CAST1` `0x1C72F` |
| `0x40` | 魯易浮標、飛行術、傳送到地面 | `2CAST1` `0x1C355`／`0x1C40A`／`0x1C93C` |
| `0x80` | root `0x14023` | — |

它**不是** `+13`：那一格是 0–100 的百分比，對百分比做
`test ..., 40h` 沒有意義。

`ds:9E33` 來自怪物記錄 `+18` 的 bit 7 ——
同一個位元組的 bit 6 進 `ds:9E32`、bit 5 進 `ds:9E28`、
低五位進 `ds:9E27`，與 `+22`／`+23` 是同一種「高位當旗標、
低位當數值」的打包。

位置是兩件事夾出來的：`2COMBAT.img` `0x13CAC` 把某個位元組的 bit 7
累加進 `ds:9E33`，而手冊說驅魔術的目標是「所有的不死怪物」。
十二個位元組逐一試，只有 `+18` 讓名字帶 Zombie／Skeleton／Ghost／
Mummy／Vampire／Lich／Wraith／Spectre／Wight 的七隻全部命中、零漏網
（全表 30 隻有旗標，其餘 23 隻的名字看不出來）。

### 傳送到地面用的三個位址

`sub_1C92A` 把地面返回點寫回隊伍位置：

	ds:0393 = ds:599C and 0Fh     ; X
	ds:0394 = ds:599C shr 4       ; Y
	ds:0392 = ds:599E             ; 地圖編號

所以 **`ds:0392` 是目前地圖編號**、`ds:599C` 是進地下城時記下的
地面座標（低 nibble X、高 nibble Y）、`ds:599E` 是地面地圖編號。
`ds:599C` 為 0 或 `ds:59A0` bit 6 成立時整條法術失敗。識別術（引 57）與神聖賜與（引 25）
是純顯示，前者印怪物資料、後者只印訊息。`internal/game/cast.go` 對它們照扣代價、
不假裝有效果（`CastResult.Effect` 是空字串）。

## 5. 誰會施法

牧師、巫師、遊俠、弓箭手。名冊四十筆裡只有牧師與巫師的法力欄位非零，
與手冊「遊俠與弓箭手要較高的經驗等級才有法力」一致。
