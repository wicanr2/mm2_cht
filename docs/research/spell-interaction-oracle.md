### `loc_16EC2` 是一支 root 常式（2026-08-14 定案）

`0x16EC2` 是 overlay thunk 表的第 26 筆，指向 **root `0x13268`**
（`tools/ovl_thunks.py 16EC2` 可重跑）。兩份匯出都看得到它，是因為兩個
overlay 的 composite image 都含同一份 root，不是兩支不同的常式。

```asm
sub_13268(lo, hi):
    do  al = sub_11A30()          ; 取一個鍵（thunk 0x16DBA）
        if al == 0x1B: break      ; ESC 直接返回
    while (al < lo || al > hi)
    return al
```

「範圍內或 ESC」是常式本身的定義，不是從呼叫端推的 —— 等級 **已證實**。

### 會收鍵盤輸入的法術 handler 只有六支

`2CAST1`／`2CAST2` 對 `loc_16EC2` 的呼叫共八處，分屬六支函式；
`loc_16DBA`（原始取鍵）在 `2CAST1` 另有三處、`2CAST2` 零處。

| 函式 | 提示 | 輸入 |
|---|---|---|
| `2CAST1 sub_1C340` | — | 走 `sub_1D046` 後另收鍵 |
| `2CAST1 sub_1C3EE` | `ds:30A7` = `Fly to (A-E)?` | **飛行術**，`A`–`E` 五選一，ESC 取消 |
| `2CAST1 sub_1C590` | 見上表 | 傳送術 `1`–`9` |
| `2CAST1 sub_1CA20` | 見上表 | 城市傳送術 `1`–`5` |
| `2CAST1 sub_1CF8C` | 提示字串第 11 個字元動態填 `'0'+隊伍人數` | **選隊員**，範圍隨隊伍人數；`word_10426 == 1` 時直接用 `'1'` 不問 |
| `2CAST2 sub_1D1A6` | 同上 | 同上 |
| `2CAST1 sub_1D046`／`2CAST2 sub_1D23A` | `ds:315E`／`ds:31E4` 都是 `'Return' to cast` | 共用確認提示，兩個 overlay 各有一份 |

**群組 C（多目標戰鬥法術）一支都不在這張表裡** —— 它們的 handler 不呼叫任何
取鍵常式，所以不會在自己的流程裡問目標。

### F. 步數／欄位仍不可定案

鷹眼術的資料寫「施法者等級×5 步／等級」，但本次沒有證據顯示玩家輸入步數；
多目標戰鬥法術的「欄位（column）」也沒有從現有匯出安全推出。這兩者先標為
**未知**，不能直接把 `Target` 數字轉成 UI 欄位。

「要不要逐隻選擇」這一半已經有答案：**不會**，理由見上一節。
但這只證明法術 handler 自己不問 —— 戰鬥主迴圈（在 root，`2COMBAT` 全檔零個
取鍵呼叫）是否在別的時點問，仍是 **未知**。

## 實機重播（2026-08-17，normal path）

前面每一節的靜態結論這一輪拿 DOSBox 重播對過了。方法與門那一輪相同：
**按鍵走正常玩家路徑，SP 用記憶體傾印讀**（角色記錄在 DGROUP `0x7E20`，
一筆 130 bytes，以 `ds:0416` 的名冊索引定位；SP 在記錄 `+88`）。
畫面只能告訴你「好像施法了」，記憶體直接告訴你什麼時候扣的。

### 施法的入口不是移動畫面的 `C`

移動迴圈的 `C` 是 **Controls**（音效／腳步聲／`Disposition`／`Delay`）。
施法在**角色卡**上：按人物編號開卡 → 卡片下方的 `'C' Cast`。
（`O` 的 `OPTIONS` 視窗列的就是移動迴圈的全部指令，裡面沒有施法，
見 [`command-keys-oracle`](command-keys-oracle.md)。）

### 提示序列

```
角色卡 → C
   ┌ Spell Book（9 列 × 7 欄的打勾表，會的打勾）
   │ Cast Spell Level: _      ← 收 1–9
   │         Number: _        ← 收 1–7
   └ 然後二選一：
       需要目標   → `On whom (1-6)?`  範圍隨隊伍人數，**答完立刻施放**
       不需要輸入 → `'Return' to cast`，按 Return 才施放
   任何一步 Esc 都回得去（畫面下方常駐 `('ESC' to go back)`）
```

`On whom (1-6)?` 證實了靜態那一條「提示字串第 11 個字元動態填
`'0' + 隊伍人數`」（`sub_1CF8C`／`sub_1D1A6`）。而**需要目標的法術沒有第二段
`'Return' to cast`** —— 目標給完就是確認，這一點靜態看不出來。

### 扣 SP 的時點：施放的那一刻，不是進選單

牧師 YOOHOO（Lvl 2、SP 14／14）連續三次傾印：

| 時點 | 畫面 | SP |
|---|---|---|
| 開卡選完急救術（L1 #4），停在 `On whom (1-6)?` | 提示中 | 14 |
| 按 `Esc` 取消 | 回角色卡 | 14 |
| 重來一次並答 `2` | 施放 | **13** |

照明術（L1 #5，無目標）同樣：停在 `'Return' to cast` 時 SP 仍是 14，
按下 Return 之後 13，而且 `ds:03D5`（照明計數）由 0 變 1。

**所以「進選單即扣」是錯的，「確認後才扣」是對的** —— remake 現在的做法
（提示子選單確認前不呼叫 `Cast`、`Esc` 不扣 SP／寶石）與原版一致。
這一條原本掛著「不得宣稱」的警告，現在結案。

### 魔法偵測術不問哪一件物品

巫師 EVILDUDE 施魔法偵測術：選完法術直接是 `'Return' to cast`，
按下之後在角色卡下方一次列出**整個背包六格的充能**：

```
Charges: A=5  B=5  C=5
         D=0  E=0  F=0
```

沒有「挑一件物品」這一步。remake 也沒有（`SpellPromptFor` 的物品提示只給
去咒術、能量補充術、複製術、加強法力這四條「對某一件物品動手」的法術，
魔法偵測術不在內），兩邊一致。

### 這一輪沒能驗到的

戰鬥中的目標提示、需要數字的兩條（傳送術、城市傳送術）與飛行術都要更高
等級的法術，預設隊伍（兩名施法者都是法力等級 1）學不到。要驗得先養等級或
另備存檔 —— 記在 [`todo.md`](../todo.md)。

### 戰鬥中的目標提示與數字提示（2026-08-17 補完，O7）

要驗這幾條得有高等級的施法者，而預設隊伍兩名都是法力等級 1。做法是
**改名冊不改程式**（`cmd/mm2roster`）：把 `ROSTER.DAT` 的可寫副本裡那兩位
的法力等級設 9、SP 200、寶石 99、等級 20、四十八條全學。跑的仍然是原版
自己的程式碼，只有「玩家練到哪」被改了 —— 與把事件搬到起點旁邊
（[`playtest/02`](../playtest/02-event-relocation.md)）同一個手法。

**戰鬥中的施法在角色自己的指令列上。** 戰鬥的指令選單是**逐角色**的，
而且會依那個角色當下能做什麼增減：

```
Options for:  A-Attack  U-Use    E-Exch          ← 施法職業才有 C-Cast
YOOHOO        F-Fight   B-Block  V-View
              C-Cast    R-Run
```

武士只有 `A-Attack F-Fight B-Block V-View U-Use E-Exch R-Run`；
打不到人的後排角色連 `A`／`F` 都不列。

四種提示的字面與範圍：

| 情形 | 提示 | 範圍 | 給完之後 |
|---|---|---|---|
| 近戰選目標（`F-Fight`）| `Fight which (A - E)?` | **前排**（`ds:9FC5`）| 立刻攻擊 |
| 法術的怪物目標 | `On which (A-J)?` | **場上全部**，夾在 10 | 立刻施放 |
| 法術的隊員目標 | `On whom (1-6)?` | 隊伍人數 | 立刻施放 |
| 無輸入的法術 | `'Return' to cast` | — | 按 Return 施放 |

**法術打得到後排。** 近戰問的是 `A - E`（前排五隻），同一場戰鬥裡法術問的是
`A-J`（場上十隻）—— 怪物名單面板兩種情形都列 `A)`–`J)`，只在打得到的那幾隻
前面打勾。這一條先前標成「未知」，現在是已證實。

### 扣費的時點分兩種

| 提示 | 在提示畫面 | 按 `Esc` | 給完之後 |
|---|---|---|---|
| `On whom (1-6)?`（急救術）| 14 | **14（不扣）** | 13 |
| `On which (A-J)?`（狂風陣 5 SP＋5 寶石）| 200／99 | **200／99（不扣）** | 195／94 |
| `'Return' to cast`（照明術）| 14 | 14（沒按就沒扣）| 13 |
| `Town (1-5)?`（城市傳送術 8 SP＋8 寶石）| 200／99 | **192／91（照扣）** | 192／91 ＋ 傳送 |
| `Squares: (1-9)?`（傳送術 5 SP）| 200 | **195（照扣）** | — |

模型很一致：**`'Return' to cast` 就是付款那一刻**。需要目標的法術用目標提示
取代那個確認（給了目標＝確認），所以在目標提示按 `Esc` 什麼都沒發生；
需要數字的法術是**先確認（付款）再問落點**，那時候按 `Esc` 只是放棄落點，
錢已經付了、隊伍不動 —— 一次白施。

**remake 與這一條不同**：數字提示排在呼叫 `Cast` 之前，所以 `Esc` 不扣。
理由與取捨記在 [`polish-spec`](../polish-spec.md) D4。

邊界值不必另外跑：收鍵的 `loc_16EC2` → root `sub_13268(lo, hi)` 本身的定義
就是「範圍內或 `0x1B`，其餘一律再讀一次」（已證實，見上面那一節），
所以按 `6` 或 `0` 在 `Town (1-5)?` 只會被忽略。

## 目前可交給實作者的最小 oracle gate

本輪能以原始位址確定的共同骨架是（全部為靜態組語，不宣稱 normal-path replay）：

1. `2CAST1`／`2CAST2` 的 handler 先呼叫 `sub_1D046`（IDA 線性 `0x1D046`；
   level-2 overlay offset `0xD846`）顯示提示並等
   Enter；取消或禁魔格會在正式效果前返回。
2. 需要數字的兩條已明確呼叫 `loc_16EC2`：傳送術 `1`–`9`、城市傳送術 `1`–`5`；
   `0x1B` 是取消，不應扣除後才取消。
3. **扣 SP／寶石時點：確認之後才扣**（2026-08-17 實機量測，見上一節）。
   停在提示畫面時 SP 未動，`Esc` 取消不扣，答完目標或按下 Return 才 −1。

## Remake 已接入的最小 UI gate（2026-08-12）

`internal/game.SpellPromptFor` 只把目前 `spellEffects` 確實讀取的輸入接到正常
施法選單：隊員索引、施法者背包槽位、傳送／城市／魯易浮標的數字，以及飛行術的
欄位與列。`internal/ui` 在提示子選單確認前不呼叫 `Cast`；`Esc` 只回到法術清單，
因此不扣 SP／寶石。提示欄位是暫存狀態，不寫入存檔；選單中的存檔鍵也不會改變
遊戲狀態。

這不是把 96 條法術的 `Target` 文字自動轉成輸入規則：尚未證實的怪物目標、欄位
選擇與其他原版提示仍維持自動效果或 fail-closed，等待對應的 DOSBox normal-path
oracle。`TestTargetedSpellPromptCanCancelBeforeCost` 與
`TestSpellItemAndChoicePromptsCanCancel` 是目前 UI 鍵路徑證據。
