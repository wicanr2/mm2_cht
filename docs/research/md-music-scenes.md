# Mega Drive 配樂的場景對照

18 首曲子分別配哪一個場景。**整條推導是反組譯，不是聽出來的** ——
理由與方法見最後一節。機制（驅動、命令介面、播放入口）在
[`md-music-driver.md`](md-music-driver.md)，擷取工具鏈在 [`../music.md`](../music.md)。

重跑：

```bash
tools/ida.sh script ida_funcs.idc md_mm2.i64        # 匯出函式邊界
docker run --rm --network none -u "$(id -u):$(id -g)" -e HOME=/tmp \
  -v "$(pwd)/workplace/genesis:/rom:ro" -v "$(pwd)/workplace/ida/out:/ida:ro" \
  -v "$(pwd)/tools:/tools:ro" -w /tmp mm2-go:latest \
  python3 /tools/md_music_scenes.py "/rom/<ROM>" /ida/funcs.txt
```

## 推導鏈

	遊戲程式碼 ──jsr $22E(a5)──▶ sub_B620(case)
	                              │
	                              ├─ 跳表 switch（21 個 case，表在 0x0B648）
	                              └─▶ 寫 RAM $FFCB62 = 曲目位址
	                                    │
	                                  vblank 音樂管理比對後換曲

**39 個呼叫端**：11 個直接 `jsr`／`bsr`，28 個走 a5 thunk（位移 558）。
**只掃直接呼叫會漏掉七成** —— 這個編譯器預設走 thunk 表。

### case 19 為什麼是「區域音樂」

三條互相獨立的證據：

1. **選曲依地圖編號**。`sub_10E56`（進入地圖）呼叫 `sub_FB86(地圖編號)`，
   回傳的區域類型寫進 `-$4C6(a5)`，case 19 就照它分支。
2. **`sub_FB86` 是區間查表**，而區間與 DOS 版的地圖編號語意完全吻合
   （見下表）—— 這是跨平台的獨立印證，不是同一份資料自說自話。
3. **每一個設施函式離開時都呼叫 case 19**：鐵匠、訓練所、神殿、酒館、
   戰鬥結束的呼叫端全部出現在 case 19 的清單裡。那正是「離開設施、
   把區域音樂放回去」的行為。

`sub_FB86`（`0x0FB86`）的區間：

| 地圖編號 | 區域類型 | DOS 版的語意（本專案既有結論）|
|---|---|---|
| 0–4 | 0 | 五座城鎮 |
| 5–16 | 3 | 野外（12 張）|
| 17–32 | 1 | 室內／地城（16 張）|
| 33–40 | 6 | 野外（8 張）|
| 41–44 | 4 | 野外 |
| 45–54 | 5 | 室內 |
| 55–59 | 2 | 室內 |
| 60 以上 | 7 | — |

野外那三個類型（3／4／6）在 `sub_10E56` 裡會把 `-$4C4(a5)` 設成 1，
case 19 據此選 `0x0B2290`。

**原版的旅店不換曲。** 旅店的程式在 `0x28xxx`（字串 `Leave the Inn`、
`leave the inn!`），而整片 ROM 最後一個選曲呼叫端在 `0x023C1E` ——
那一區一個都沒有。所以進旅店時聽到的是當下的區域音樂，
音樂包讓 `inn` 沿用 `town` 是照原版行為，不是找不到就隨便填。

三首沒有對應到角色：`0x0BAE7C`（case 4）與 `0x0B60CC`（case 20）在整片 ROM
裡沒有任何呼叫端，這個移植版沒有用到；`0x0BA608`（case 11）有呼叫端
（`0x018BCA`，且同一支函式在 `0x018BB6` 也請求 case 19，是設施的進出樣式），
但字串錨點離得太遠（`Identify Item` ±953），**不足以定是哪一個設施，所以留白**。

## 為什麼不用聽的

**「聽起來像城鎮」不是證據。** 換一個聽的人就換一個答案，沒辦法重跑，
也沒辦法在資料更新後自動驗證。反組譯得到的是「程式在什麼情況下播這一首」，
那是遊戲自己的定義。

代價是要多解三層（呼叫端 → case → 曲目），而且中間有兩個地方會靜默失敗：
**呼叫端要連 thunk 一起掃**（漏掉七成），**字串錨點要整批一致才算數**
（單一一筆可能只是資料排在附近的巧合）。這兩件事都比「聽一遍」慢，
但只有它們的結論可以被下一個人重跑並推翻。

MM2 的文字**不用絕對指標也不用 PC 相對引用**（與 DOS 版一樣走索引表），
所以拿不到「這支函式引用了這條字串」的精確關係，只能用位置。
這是上表多數列標「強推論」而不是「已證實」的原因。
要升級成已證實，得解出文字索引表並改用精確引用。
