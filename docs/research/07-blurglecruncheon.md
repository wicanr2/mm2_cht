# Blurglecruncheon 的 MM2 攻略站調查

作者：Andrew Schultz 
最後更新：2001-03-01
取用日期：2026-08-18
網址前綴：`http://www.geocities.ws/blurglecruncheon/mm2/`

Geocities 上一個 1990 年代的 MM2 攻略與地圖資源站。主要內容包括手繪地圖、逐部門玩法攻略、傭兵清單與已知 bug。

## 1. 頁面概況

### main.htm — 索引頁

**內容型態**：文本索引 + 表格框架
**規模**：不到一頁

主頁介紹作者在高中時期喜愛 MM2，認為相比 MM1 更規律、更容易由一個人逆向。

列出的主要內容項：
- 地圖（已色化中）
- 攻略（FAQ 與走完整流程的 walkthrough）
- 世界地圖拼圖（「strung together a patchwork world map」）
- 傭兵（hireling）頁面
- 原版 bug 清單

提及「幾乎完成了所有地圖，並找到所有 MM2 的物品與怪物」。該站是 WebRing 會員（一個 1990 年代的網站連結網絡）。

### maps.htm — 地圖索引

**內容型態**：表格索引 + 文本描述
**規模**：約 30 張圖與對應的 HTML 連結

按類別組織的地圖：
- **戶外地圖**：Cron 的 5×5 網格世界（A–E 行，1–5 列），加上完整世界地圖
- **五個城鎮**：Middlegate、Atlantium、Tundara、Vulcania、Sandsobar，各含城鎮圖與地下城圖
- **洞窟**：13 個，按字母順序列出（Corak's Cave、Dawn's Mist Bog、Dragon's Dominion 等）
- **城堡**：Woodhaven、Hillstone、Pinehurst、Luxus Palace，各含表面與兩層地下城
- **元素平面**：Fire、Water、Earth、Air 各一張

頁面明確標示「Woodhaven Level 2 還在開發中」（尚未完成），大多數 HTML 連結當時標示為有效。

仍是提問（等級 `未知`），逐條裁決列在 [`docs/todo.md`](../todo.md) 的 O8。

**查之前先翻 [`docs/re/`](../re/)。** Bug 1 要的那三十路附帶效果表
（含「吸經驗，不夠就歸零」）早就整理在
[`09-2combat-map.md`](../re/09-2combat-map.md) §3.3，而這一輪是重新反組譯
才發現的。[`00-function-index.md`](../re/00-function-index.md) 查得到函式名。

**站上說對了不代表成因也對。** Bug 3 就是這種：現象存在與否要看平台，
而站上給的成因（線性索引減一）與 DOS 版的碼對不上。裁決要裁到**機制**那一層，
只確認「有沒有這個現象」等於沒裁。

原版的 bug 對 remake 是**要知情地決定**的東西：照抄還是修掉都行，
不知道它存在而「順手修掉」不行。

**Bug 1：Dead Heads 角色經驗與血量溢位**
- 現象：Dead Heads 攻擊低等級角色時，角色會失去經驗與生命值。若血量降到零以下，會循環回復到接近 65536（2^16）。
- 觸發條件：Dead Heads 在低等級角色戰鬥中攻擊造成大傷害
- **這一條查完了：DOS 版重現不了 —— 每一處減法都有下限守衛**（2026-08-20，
  推論等級 `已證實`，靜態組語）。經驗值確實會被吸，但不會回捲。

  **經驗值**（近身命中的附帶效果碼 27，`2COMBAT` 的 `sub_1AF04`）扣
  `rand(1,80) + 20`，用 32 位比較（先比高位 `+100` 再比低位 `+98`）；
  扣不動就 `sub ax, ax` 把兩個 word 都寫 0。21–100 點對高等級角色是零頭，
  對一級角色是整條命 —— 站上說「低等級角色」正是這個原因。

  **生命值**只有**一處**減法，在 root `0x13A4B`，而且前面就是守衛：

  ```
  013A39  cmp  [bx+5Eh], ax        ; 目前生命 vs 傷害
  013A3C  ja   short loc_13A48     ; 撐得住 → 正常扣
  013A3E  or   byte ptr [bx+26h], 40h  ; 撐不住 → 昏迷
  013A42  inc  byte ptr [bp-2]
  ...
  013A48  sub  [bx+5Eh], ax
  013A4E  cmp  byte ptr [bp-2], 0
  013A54  mov  word ptr [bx+5Eh], 0   ; 昏迷那一路把生命寫 0
  ```

  **等級與屬性**走共用的 `sub_1AB3E(欄位指標, 量)`，同樣先比再扣：
  扣不動就寫 0 **並把狀況設成 `0x81`（死亡）**。

  掃描樣式寫在這裡好讓下一輪知道覆蓋到哪：十四個 `.img` 加 `MM2.EXE`
  逐條指令掃**運算元位移等於 `0x5E`** 的寫入端，全部命中只有上面那一條
  減法與兩處寫 0（另有復活、休息、建角色等寫入）。指標間接的寫法
  （像 `sub_1AB3E` 那樣傳 `記錄 + 偏移` 進來）掃不到，所以另外查了
  它的三個呼叫端 —— 都是屬性與等級，沒有生命。

  站上描述的 65536 可能出自別的平台版本。**我們不追**（沒有那些版本的
  執行檔可以裁決），DOS 版照現況即可，remake 不必加溢位。

**Bug 2：Druid 沈默咒語的法術仍可施放**
- 現象：Druid 施放 Silence 後，隊伍在戰鬥外仍可施放法術。
- 觸發條件：被 Druid 沈默後離開戰鬥
- **這一條查完了：站上說得對，而且原版的擋人條件裡根本沒有沈默**（2026-08-20，
  推論等級 `已證實`，靜態組語）。角色卡的指令分派 `sub_158B0` 在 `'C'`（施法）
  那一格連做三道檢查（root `0x159E6`–`0x15A05`）：

  ```
  0159E6  mov  bx, [bp+var_6]        ; 角色記錄
  0159E9  cmp  byte ptr [bx+23h], 0  ; ① 基礎法力等級為 0 → 不能施法
  0159ED  jnz  short loc_159F2
  0159EF  jmp  def_159E0
  0159F2  cmp  [bp+var_4], 80h       ; ② 狀況 >= 0x80（石化／死亡／抹消）→ 不行
  0159F6  jb   short loc_159FB
  0159F8  jmp  def_159E0
  0159FB  test [bp+var_4], 70h       ; ③ 昏迷 0x40／麻痺 0x20／沈睡 0x10 → 不行
  0159FF  jz   short loc_15A04
  015A01  jmp  def_159E0
  015A04  push bx
  015A05  call sub_15D44             ; 進施法流程
  ```

  `var_4` 是 `0x15903` 從記錄 `+0x26`（狀況位元組）讀進來的。
  **遮罩 `0x70` 不含 `0x02`（沈默），`0x01`（詛咒）、`0x04`（疾病）、
  `0x08`（中毒）也都不含** —— 所以沈默在戰鬥外一律不擋施法。
  這不是溢位或邊界錯誤，是遮罩本來就沒有收這一位。

  找法：`Cast Spell Level: ` 在 DGROUP `ds:50DC`，掃全部映像的運算元
  只有 root `sub_1554A` 用到（`mov ax, 50DCh`），往上一層是 `sub_15D44`，
  再往上就是 `sub_158B0` 的指令分派。**三層都只有一個呼叫端**，
  所以這條路徑是唯一的。

- **remake 的狀態：巧合地相同，但另一個方向錯了。** `game.Session.Cast` 
  完全不看狀況位元組（`internal/game/cast.go`），所以沈默不擋 —— 與原版
  同結果。但 UI 的施法者選單濾的是 `Condition.Acts()`，而 `Condition` 只在
  `0x80`（嚴重）與 `0x40`（昏迷）時才變 —— **沈睡 `0x10` 與麻痺 `0x20`
  在 remake 沒有對應的 `Condition`，所以那兩種狀態下 remake 讓人施法，
  原版不讓**。這一項**還沒改**：要改之前得先解出原版**戰鬥中**對隊員的
  擋人條件（目前只解出怪物那一側的 `ds:9F86`，見
  [`08-combat.md`](../formats/08-combat.md)「沈默只有一個作用」），
  否則會照到一半。列在 [`docs/todo.md`](../todo.md)。

**Bug 3：Etherealize 傳送邊界錯誤**
- 現象：從 (0,0) 向西傳送會抵達 (15,15)；從 (x,0) 向西傳送會抵達 (x,15)。
- 觸發條件：在指定座標使用 Etherealize（乙太化）法術向西
- **這一條查完了：站上的說法與 DOS 版的碼對不上**（2026-08-20）。
  `sub_1C722` 是兩個軸各自 `and 0Fh`（`ds:0393` 與 `ds:0394` 分開遮罩），
  不是把 `Y*16+X` 當線性索引減一。從 (0,0) 往西只有 X 繞回去，落點是 **(15,0)**；
  站上寫的 (15,15) 要靠線性索引才成立。我們的 `internal/game/cast.go` 照碼寫，
  **不必改**。站上描述的可能是別的平台版本或記錯，我們不追（推論等級：`已證實`，
  反組譯見 [`docs/formats/09`](../formats/09-spells.md)「穿透術」）。
- 順帶解出兩個先前沒記的副作用：`ds:0395 = 1`（要求重畫）與 **`ds:039B = 0`**，
  後者讓穿牆落地**不觸發落點那一格的事件** —— 我們的實作剛好也不觸發
  （施法不走 `settleEvent`），行為相同但先前是碰巧對的，現在有依據了。

**Bug 4：Enchant Item 法術消耗計算錯誤**
- 現象：Enchant Item 有時會減少不正確的法力點數（差 512 倍），導致提升等級越高消耗法力越少（例如 +15 比 +5 便宜）。
- 觸發條件：施放 Enchant Item 時
- **這一條查完了：確實有異常，但方向與站上相反**（2026-08-20，推論等級
  `已證實`，靜態組語）。

  施法的扣費不是算完就定案。法力代價算好之後放在 `ds:9E0C`
  （root `sub_13AEA` 從 `SPELLS.DAT` 算），而**扣費排在效果之後**
  （root `sub_15D1A`，由 `sub_15D44` 在處理常式回來、且 `ds:0428` 非零時才呼叫）。
  中間那一段裡，處理常式可以把 `ds:9E0C` 換掉 —— 加強法力就換了：

  ```
  01C79F  and  al, 3Fh              ; 物品屬性欄 +70 的低六位＝目前附魔等級
  01C7A1  mov  [bp+var_2], al
  01C7A4  mov  al, 32h              ; 50
  01C7A6  mul  [bp+var_2]           ; AX = 50 × 等級
  01C7A9  mov  word_19E0C, ax       ; ← 把法術表算出來的代價整個覆寫掉
  01C7AC  cmp  [bx+58h], ax         ; 記錄 +88（法力，此時還沒扣）夠不夠
  01C7AF  jnb  short loc_1C7B6
  01C7B1  call sub_1CEFA            ; 不夠 → 報錯收工
  ```

  所以實際扣的是 **`50 × 施法前的附魔等級`**：

  | 施法前的等級 | 扣掉的法力 |
  |---|---|
  | 0 | **0**（免費升到 1）|
  | 5 | 250 |
  | 15 | 750 |

  **越高越貴，不是越便宜**，而且 512 這個倍數在碼裡沒有出處
  —— `mul` 是 8 位乘法（`50 × 63 = 3150` 不會溢位），word／byte 也沒有取錯。
  站上說的方向與這段碼對不上；真正異常的是「檢查的是法術表那一筆、
  扣的是覆寫後的值」，以及**等級 0 免費**。

- **remake 已經對齊**：`internal/game/cast.go` 的 `empower` 改成覆寫這一輪的
  代價（`Session.castCostSP`），`Cast` 在效果之後重算，
  `TestBuffSpells` 釘住 0 級免費、1 級 50、3 級 150。

- **順手解掉一個掛了很久的未解項**：查扣費時看到寶石那一份走 `sub_154EE`，
  它 `and 3Fh` 之後「大於 50 就折成 100」—— **寶石欄是六位不是四位**。
  `docs/formats/02` 原本記著「五條寶石消耗超過 15，一個 nibble 放不下，
  高位怎麼編碼還沒解」，這下解了，而且 remake 一直**少收**：
  複製術收 15 顆（該收 100）、加強法力與去咒術收 2 顆（該收 50）、
  神之干涉與星爆術收 4 顆（該收 20）。已修。

- Remake 考量：**敵人旗標未持久化**。可能只在戰鬥時設置旗標，存檔沒有保存，或離圖/關機後重置。

**Bug 6：水域平面休息後邊界錯誤**
- 現象：在水平面休息後，嘗試越過邊界（例如東邊從 15,3）會看到「can't swim」訊息。
- 觸發條件：在水平面休息（rest），然後嘗試移動超出邊界
- **這一條查完了：休息會把水行術關掉，站上說得對**（2026-08-20，推論等級
  `已證實`，靜態組語）。`2MISC` 的 `sub_1CD8A`（休息）開頭十三行把
  `ds:03D5`–`ds:03E1` 整段寫成 0，其中 `ds:03D9` 就是水行術旗標
  （見 [`water-traversal-oracle`](water-traversal-oracle.md)）：

  ```
  01CD92  sub  al, al
  01CD94  mov  byte_103DA, al
  01CD97  mov  byte_103D9, al   ; ← 水行術
  01CD9A  mov  byte_103D8, al
  ...     （一路清到 ds:03E1）
  ```

  水平面上沒有水行術就走不動，所以休息完再走就吃到「can't swim」。
  **這不是水平面特有的**，照明術、飄浮術那一段旅行效果一起被清掉 ——
  換圖走的是同一支。設計上它與「休息回復生命與法力」是同一次結算，
  照抄比較合理。

- **remake 已經一致**：`RestAtInn` 呼叫 `World.ClearTravelEffects()`，
  清的是同一段 `0x03D5`–`0x03E1`。

**Bug 7：Nature's Gate 從城堡 Xabran 傳送目標錯誤**
- 現象：從城堡 Xabran 施放 Nature's Gate 會回到 900 年代，但休息或進城鎮會「調整」位置。
- 觸發條件：在 Castle Xabran（800 年代）施放 Nature's Gate
- **這一條查完了：站上把兩件事接在一起了，而「調整位置」是設計不是 bug**
  （2026-08-20，推論等級 `已證實`，靜態組語）。

  世紀放在 `ds:03CA`（十格日期／年份表的槽號，9 ＝ 現代）。自然之門
  `sub_1C7DA` 第一道檢查就是 `cmp word_103CA, 9; jnz 失敗` ——
  **人在 800 年代時這條法術根本開不了門**，不會「把你送回 900 年代」。

  真正把人送回現代的是**休息**。`2MISC` 的 `sub_1CD8A` 在隊員結算完之後：

  ```
  01CEA3  cmp  word_103CA, 9
  01CEA8  jz   short loc_1CEDB       ; 已經在現代 → 什麼都不做
  01CEAA  push 3Ch                   ; rand(1, 60)
  01CEAE  push 1
  01CEB2  call sub_16F76
  01CEB8  cmp  ax, 0Ah
  01CEBB  jge  short loc_1CEDB
  01CEBD  mov  word_103CA, 9         ; ← 回現代
  01CEC3  push 0FFh                  ; X = Y = 0xFF → 該圖的預設入口
  01CEC6  push ax
  01CEC8  sub  ax, ax
  01CECB  call loc_16ED9             ; 重新進圖
  ```

  擲 1–60 小於 10 就成立 —— **六分之一，平均六次休息**。這與《軟體世界》
  攻略寫的「拿到四碟之後一直用 Rest，大約七八次就能睡回現代」對得上，
  而且 `X = Y = 0xFF` 正是「位置被調整」的來源：它不是算錯，是叫地圖
  用自己的預設入口。**回現代的唯一機制就是這個**，不是 bug。

  順帶：自然之門在現代、日子 `>= 150` 時會把 `ds:03CA` 設成 8 並送到
  索引 11 的落點 —— 那是**把隊伍送進另一個世紀**，不是把法術鎖起來
  （鎖起來只是副作用，因為前提要 9）。`docs/formats/09` 原本寫「任務有時限」，
  已改寫。

**Bug 8：屬性氣球膨脹 (Stat Balloon Exploit)**
- 現象：裝備可能增加屬性的物品，令該屬性變為零，然後脫掉再穿上，該屬性會變成正數並疊加。
- 觸發條件：裝備增加某屬性的物品 → 交易該屬性至零 → 脫掉物品 → 重新裝備
- Remake 考量：要查的是屬性交易與裝備加值的先後順序 —— 我們的實作是先算基礎值
  再疊裝備，還是像站上描述的那樣讓兩者互相污染。

**Bug 9：喝泉水提升法術等級邊界**
- 現象：在 C1 (1,11) 的噴泉喝水可將法術等級提升到 9。副作用是電腦會讓騎士/野蠻人/忍者/盜賊獲得法術選項，但他們沒有可施放的法術。
- 觸發條件：喝 C1 (1,11) 的特殊噴泉
- **查到一半（2026-08-20）**：解出了這一條要用的欄位，但還沒追到泉水寫哪一個。

  **角色記錄 `+35`（`0x23`）是「基礎法力等級」，`+114` 是「當前法力等級」。**
  兩者的關係與 `+32`／`+113`（等級）、`+39`／`+115`（耐力）同一種：
  一份基礎、一份當前。證據三條：

  1. 名冊 16 個角色逐筆 `+35 == +114`，而且只有牧師與巫師非零。
  2. **只有三處讀 `[reg+0x23]`，一處都沒有寫**（掃 root、`2CAVES`、`2CAST1`、
     `2TEMPLE`、`2CMDS` 的全部運算元）：root `sub_158B0` 的施法閘門、
     root `sub_13572`、以及 `2TEMPLE` 的 `sub_1C3A0`／`sub_1C4A2`
     兩處 `cmp [bx+23h], al` —— 神殿賣法術時拿法術等級跟它比。
  3. `internal/game/cave.go` 的 `slideHalved` 已經記著 `+114` 是「當前值」
     那一組的一員（`+106` 當前陣營、`+107`–`112` 當前屬性、`+113` 戰鬥等級、
     `+114` 法力等級、`+115` 耐力）。

  **所以「能不能施法」在原版是資料欄位（`+35`）決定的，不是職業。**
  remake 的 `game.CanCast` 是**照職業**判的（`internal/game/cast.go`），
  這是一個結構性的差異：原版把 `+35` 設成非零就能讓武士開施法選單，
  remake 不論資料怎麼寫都不行 —— 站上描述的「騎士會拿到法術選項」
  在 remake 重現不了。

  **還沒查的**：C1 (1,11) 那口泉水的事件寫的是 `+35`、`+114` 還是兩個都寫。
  站上說武士拿得到選項，那就得寫到 `+35`；但這要追事件腳本才算數，
  不能從症狀反推。列在 [`docs/todo.md`](../todo.md)。
