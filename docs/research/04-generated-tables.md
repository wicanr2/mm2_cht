# 五張從原版表格萃出來的規則表：它們是什麼、MM2 當年怎麼算

git 歷史裡有五份由原版產生的 JSON：`data/creation.json`、`experience.json`、
`pictures.json`、`terrain.json`、`traps.json`。工作區已經不追蹤它們
（remake 執行時從玩家自備的原版重新萃取），但舊 commit 裡還在 ——
處置的決定與理由見 [`release.md`](../release.md)、清單見
[`todo.md`](../todo.md) 的 R1。

這一份不是處置紀錄，是**內容的考證**：那五張表各自對應 MM2 的哪一條規則。
每一張都標了 DGROUP 位址，回頭查得到。

## 1. 建角與神殿：`creation.json`

出處 `MM2.EXE` DGROUP `ds:06E6`／`06F2`／`071E`／`074D`／`46A8`。

**生命值是「職業底值 ＋ 體質加成」**。八個職業的底值差距很大 ——
騎士 9、聖騎士與弓箭手 7、盜賊與忍者 5、牧師與術士 5，而**野蠻人 12**
是全場最高；巫師 3 是最低。這一條解釋了為什麼 MM2 的巫師必須躲在後排：
它的生命值起點只有野蠻人的四分之一。

加成表是**以屬性值當索引的 23 格查表**，不是公式。三張表共用同一個形狀：

- 體質 → 生命值加成：前兩格是 5 與 12（屬性 0、1 的特例），之後從 0 起
  慢慢爬到 8。
- 智力／人格 → 法力加成：與生命值那張**逐格相同**（8, 8, 1, 1, 1, 1, 2…）。
- 敏捷 → 護甲：前十二格全是 0，屬性到 12 以上才開始給，最高 5。

「前兩格是特例」是查表法的典型痕跡：屬性 0 與 1 在遊戲裡不會正常出現，
那兩格擺的是溢位保護值，不是設計上的獎勵。

神殿的收費倍率是五格（1、5、2、3、2），依處理的項目挑 —— 復活最貴。

## 2. 升級曲線：`experience.json`

出處 `MM2.EXE` DGROUP `ds:2E5C` 的表，加上 `2MISC2` `sub_CC8C` 處理
11 級以上的分段。

**十級以前是兩條倍增數列**：

| | 2 級 | 3 級 | … | 10 級 |
|---|---|---|---|---|
| 快 | 1,500 | 3,000 | 每級 ×2 | 384,000 |
| 慢 | 2,000 | 4,000 | 每級 ×2 | 512,000 |

走「慢」的是四個職業（索引 1、2、4、6）。**十一級以後改成固定級距**，
而且級距分段加大：

| 從幾級 | 每級要多少 |
|---|---|
| 11–13 | 192,000 |
| 14–15 | 384,000 |
| 16–20 | 768,000 |
| 21–30 | 1,536,000 |
| 31–50 | 3,072,000 |
| 51–75 | 1,638,400 |
| 76 以上 | 6,144,000 |

51–75 那一段**比前一段便宜**（1,638,400 < 3,072,000）——曲線在這裡凹下去
再翹上來。這不是抄錯：`sub_CC8C` 的分段就是這樣寫的，兩個值在二進位裡
差很遠（`0x2E0000` 與 `0x190000`），不是相鄰的鍵盤誤打。

## 3. 怪物圖號：`pictures.json`

出處 `MM2.EXE` DGROUP `ds:164C`／`1662`／`167C`／`1694`／`16AC`，
使用端是 `sub_18EE6`。

**五張各 26 格的表**，`scene` 那七格（0, 2, 4, 1, 3, 4, 3）把場景碼對到
要用哪一張。也就是：同一隻怪在不同地形會挑到不同的圖號 —— 這是 MM2
用一套怪物資料撐出視覺變化的做法，怪物本身沒有多份美術。

## 4. 地形分類：`terrain.json`

出處 `MM2.EXE` DGROUP `ds:52B2`，32 項；使用端 `sub_5F40` 先把碼 `& 0x1F`
再查。分類值只有 0–4 五種：

| 值 | 意思 |
|---|---|
| 0 | 什麼都不畫 |
| 1–3 | 三組擋路物之一 |
| 4 | 地平線的地形帶 |

三十二格裡真正用到的集中在前十三格（`0,1,1,2,3,4,4,4,4,4,4,4,4`），
之後只有第 28 格是 4，其餘全 0。**野外視圖每一格畫什麼就是查這張表**，
見 [`formats/04`](../formats/04-graphics.md)「野外是另一條路徑」。

## 5. 陷阱：`traps.json`

出處 `MM2.EXE` DGROUP `ds:2946`（傷害）與 `ds:28F2`（訊息）。

**五種寶箱各有自己的傷害底值**（3、4、4、5、6），而**訊息只有四條**
（電擊、火焰、毒氣、尖刺），五種箱子共用同一組四則。開箱失敗先印
`Explosion!`（`ds:2950`），再印四則之一。

底值 3–6 的差距很小，說明陷阱傷害的主要來源不是箱子等級而是別的乘數 ——
這一點在 [`formats/02`](../formats/02-data-files.md) 的寶箱那一節有完整的
計算鏈。

## 為什麼這些值不寫死在 remake 裡

寫死等於把原版資料複製進版控。remake 的做法是**執行時從玩家自備的原版
萃取**（`cmd/mm2data`），所以公開的程式碼裡只有「怎麼算」沒有「算什麼」。
上面這些數字寫在文件裡是考證，不是程式的輸入 ——
改了這一頁不會改變遊戲的行為。
