# 門的開啟狀態 —— 存在哪裡、活多久

## 結論

門的開啟狀態存在**當前地圖的屬性層 `ds:5AD6`**（256 bytes，一格一個 byte），
不在地形層，也沒有第二份備份。

| 問題 | 答案 | 等級 |
|---|---|---|
| 成功後改了什麼 | `attr[格] ^= (terrain[格] & 方向遮罩) >> 1` —— 把該方向的牆位元翻掉 | 已證實 |
| 誰做這件事 | root `sub_13A64`，overlay 經 thunk `0x1765A` | 已證實 |
| 誰呼叫它 | 只有 `2MISC` 兩處：撞門成功 `0x1C20F`、開鎖成功 `0x1C326` | 已證實 |
| 地形層會不會變 | 不會。全十五個資料庫只有一處寫地形層，是事件腳本改地圖的 opcode | 已證實 |
| 開門翻幾側 | **只翻站的那一格**。對面那一格的牆位元不動，所以走進門後那一格之後，回頭那一步是擋著的 | 已證實（實機記憶體）|
| 前進、轉身、同圖內走動 | 保持開著（`sub_1BE24` 由地圖編號守門，不重載）| 已證實（實機記憶體）|
| 離圖再進 | **關回去**。屬性層從 `MAP.DAT` 重讀 | 已證實（實機記憶體：回到原圖時整層與檔案逐位元相同）|
| 存檔重載 | 同上，讀檔後換圖一樣觸發重載 | 強推論 |
| `MAP.DAT` 會不會被改寫 | 載入器 `sub_160ED` 只用 `int 21h` 的 `3Dh`／`42h`／`3Fh`／`48h`／`49h`，沒有 `40h`；其他常式是否會寫同一個檔沒有掃過 | 載入器已證實，全檔未掃 |

推導鏈與位址在 [`docs/formats/06-map.md`](../formats/06-map.md)
「執行時的地圖緩衝區：誰載入、載入什麼」。

**同一個生存期還蓋到事件旗標。** 屬性層 bit 7 是「這一格有事件」，
事件 opcode `0x14` 清掉它表示用過了 —— 它跟門一樣，換圖就整層重讀。
remake 若把「事件只觸發一次」做成永久旗標，離圖再回來的行為會與原版不同。

反過來，自動地圖的走訪位元是另一份陣列（`ds:968C`，60 × 32 bytes），
以地圖編號索引，**不隨換圖重載**。兩者不要混在一起實作。

## 兩條開門路徑

`2MISC` 的兩個指令 handler，成功後都呼叫同一支 `sub_13A64`。

**撞門 `_2misc_e00`（`0x1C14E`）**

```
var_4 = (地形層[格] >> ds:59C7) & 3        ; 該方向的兩位元值
ds:039D == 1                     → 訊息 0xF2 + 重繪（室內外分流）
var_4 == 0                       → 同上（那個方向沒有東西）
(ds:59C8 & ds:59C6) & 55h == 0   → 同上（牆位元已經被翻掉 = 門開著）
var_4 != 2                       → 訊息 1（不是門）
力量 = 隊員[0] 的 +0x6B，隊伍 >1 人再加隊員[1] 的 +0x6B
擲 = rand(10,109) / 10
  擲 == 5                        → 直接成功
  力量 + 擲 >= ds:5998           → 成功        ; ATTRIB +18 撞門難度
  否則                           → 訊息 2（失敗）
成功後再擲 rand(1,100)：
  >= 51 → sub_13A64 開門，走訊息 0xF2 + 重繪
  <  51 → sub_1C41E 抽傷害、sub_1C390 施加到隊伍、ds:0430 = 3、重繪
```

**開鎖 `_2misc_e01`（`0x1C26E`）**

```
(地形層[格] >> ds:59C7) != 2               → 直接返回（不是門）
((地形層[格] & ds:59C6) >> 1) & ds:59C8 == 0 → 訊息 3（門已經開了）
sub_1C7AA 選人；回 0x1B → 走 loc_1728E 返回
擲 = rand(1,100)；技能 = 該員記錄 +0x1E
  擲 < 0x60 且 技能 >= 擲 → sub_13A64 開門 + 訊息 4（Success!）
  否則 再擲 rand(1,100)：
    ds:5999 >= 擲 → 訊息 2（失敗）    ; ATTRIB +19
    否則          → 陷阱：sub_1C41E、sub_1C390、ds:0430 = 3、重繪
```

**撞門成功不顯示 `Success!`**，直接開門重繪；`Success!`（訊息 4）只有開鎖有。

## 實機複驗（2026-08-17，已完成）

靜態證據早就把三個問題（改哪裡、誰改、活多久）答完 —— 屬性層的**全部**
寫入端只有六處，`MAP.DAT` 的寫入端是零（`tools/ida_dsuse.py` 掃十五個資料庫
比對運算元的位移值；**不能用 xref 圖**，`[reg+disp]` 形式 IDA 不建 data xref，
查出來的零與「真的沒人碰」長得一模一樣）。實機這一輪是**事後複驗**，
兩件事都量到了。

驗的方法不是看畫面，是**傾印 DOSBox 的記憶體讀屬性層本身**
（`ds:5AD6` 起 256 bytes，DGROUP 基底的找法見 [`playtest/02`](../playtest/02-event-relocation.md)）。
畫面只能告訴你「門好像開了」，記憶體直接告訴你哪一個位元變了。

**一、撞門翻的是屬性層的牆位元**

米德格特（地圖 0）真正**關著**的門只有六道（判準是屬性層的牆位元 ＝ 1，
不是地形層那兩位元 —— 地形說「那一面是門」，屬性說「擋不擋路」）。
最近的一道在 `(10,3)` 的北面，離起點十一步。

| 傾印 | 位置 | 格 58 屬性 | 北牆位元 | 北地形 |
|---|---|---|---|---|
| 撞之前 | (10,3) | `11010000` | 1 | 2（門）|
| 撞開之後 | (10,4) | `10010000` | **0** | 2（門）|
| 又走了幾步 | (10,4) | `10010000` | 0 | 2（門）|

翻掉的正是 bit 6（北），而且**地形層一個位元都沒動** ——
`attr ^= (terrain & mask) >> 1` 逐位元對得上。同圖內繼續走動、
甚至打完一場遭遇戰，位元都維持 0。

**二、換圖時屬性層整層從 `MAP.DAT` 重讀**

米德格特 `(8,0)` 面西是往下層洞窟的樓梯（事件 `0x0c` → 地圖 17 的 `(15,8)`，
畫面問 `Stairs to Cavern. Descend (y/n)?`）。下去再上來，逐位元比對：

| 傾印 | 執行時地圖 | 屬性層與 `MAP.DAT` 地圖 0 的平面 |
|---|---|---|
| 進城後在 (7,3) | 0 | 相同 |
| 走到 (10,3) 之後 | 0 | **不同**（沿路事件把 bit 7 清掉了）|
| 下到洞窟 (15,8) | 17 | 不同；改與**地圖 17 的平面**逐位元相同 |
| 回到 (8,0) | 0 | **又完全相同** |

最後一列就是結論：**回到原圖時，記憶體裡那一層與檔案裡的一模一樣** ——
路上清掉的事件位元、撞開的門，全部消失。所以門會關回去不是推論，
是「整層重讀」的必然結果。

**三、順帶量到的：開門只翻一側**

開門改的是**站的那一格**的牆位元。`(10,3)` 的北牆翻掉之後，
`(10,4)` 的南牆位元仍然是 1 —— 隊伍走進門後那一格，**回頭那一步是擋著的**，
要退回去得從另一側再撞一次。`internal/game` 的 `OpenDoor` 只 patch 當前格，
`CanMove` 讀的是來源格的牆位元，兩邊語意相同。

排路與按鍵序列由 [`cmd/doorprobe`](../../cmd/doorprobe) 從 `MAP.DAT` 直接算
（哪幾道門是關的、怎麼走過去、轉向怎麼下、屬性層平面的十六進位）——
**DOSBox 一輪要好幾分鐘，路線用猜的會白跑**。踩到的三個坑寫在那支的註解裡：
訊息會吃掉按鍵（每走一步補一個 `space`）、樓梯要回答 `y` 不是 `space`、
`workplace/dosbox/game/` 會留著上一輪的存檔（Day 13 的隊伍站在別的地方），
重跑前先刪掉。

## 前兩輪為什麼沒成功（保留存證）

前兩輪 DOSBox 窄任務都沒能觸發一次成功開門。原因這一輪才看清楚：
**它們挑錯了門**（`(10,3,N)` 是對的那一道，但當時用的是 `U` 開鎖，
成功率吃技能而預設隊伍沒有盜賊）、而且**只看畫面**——
撞門成功不印 `Success!`，畫面上與什麼都沒發生長得一樣。
這一輪改成量記憶體，第一次就分得出來。

原版從乾淨自備資料啟動，未使用 debug hook。`Return → S → G → Z` 穩定進到中門
第一人稱走廊；第二輪另抵達地圖 0 候選門 `(10,3,N)` 並由正常 `U` 指令操作，
只得到既有事件／噴泉文字。截圖在 ignored 的 `workplace/dosbox/shots/`。
